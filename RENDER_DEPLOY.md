# Insolvency Radar – Render backend integration

This upgrade keeps the existing GitHub Pages search page and weekly ASIC data collector. It adds a separate FastAPI customer API for accounts, private watchlists and Stripe Checkout.

## Before deploying

1. Keep a backup of the current GitHub repository and `leads.json`.
2. The frontend API URL is deliberately a placeholder in `index.html`. Do not publish the customer features until the Render service is deployed and the URL is configured.
3. The current MVP uses SQLite on a Render persistent disk. The disk is required: a normal Render free web service has an ephemeral filesystem and can lose customer data on restart/redeploy. The supplied `render.yaml` declares a Starter web service and a 1 GB persistent disk. Check current Render charges before creating it.
4. Create a Stripe account suitable for your Australian business. Create three recurring monthly Prices in AUD, then copy their `price_...` IDs. Do not activate live payments until your business, tax, refund, privacy and consumer-law details are ready.

## Deploy to Render

1. Push this updated repository to GitHub.
2. In Render, choose **New + → Blueprint** and select `saanjeev-bharat/insolvencys-radar`.
3. Render should detect `render.yaml`. Review the service and disk costs before confirming.
4. After creation, open the `insolvency-radar-api` service → **Environment**.
5. Set these values:
   - `STRIPE_SECRET_KEY`: Stripe test secret key initially (`sk_test_...`).
   - `STRIPE_PRICE_STARTER`: monthly AUD Starter Price ID.
   - `STRIPE_PRICE_PROFESSIONAL`: monthly AUD Professional Price ID.
   - `STRIPE_PRICE_BUSINESS`: monthly AUD Business Price ID.
   - `STRIPE_WEBHOOK_SECRET`: add after creating the webhook endpoint below.
   - `FRONTEND_URL`: `https://saanjeev-bharat.github.io`.
   - `CORS_ORIGINS`: `https://saanjeev-bharat.github.io`.
   `RADAR_SECRET_KEY` is generated by the Blueprint. Never share it or commit it to GitHub.
6. Deploy. Confirm `https://YOUR-SERVICE.onrender.com/api/health` returns `{"ok":true,...}`.
7. In Stripe Developers → Webhooks, add `https://YOUR-SERVICE.onrender.com/api/billing/webhook`. Subscribe to:
   - `checkout.session.completed`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   Copy the signing secret into `STRIPE_WEBHOOK_SECRET` in Render and redeploy.

## Connect the live GitHub Pages website

In `index.html`, replace:

```js
var API_BASE = window.RADAR_API_BASE || "https://YOUR-RENDER-SERVICE.onrender.com";
```

with your real Render URL, for example:

```js
var API_BASE = window.RADAR_API_BASE || "https://insolvency-radar-api.onrender.com";
```

Commit and push the change. The GitHub Pages public search and existing `leads.json` remain in place. Customer accounts and private watchlists are stored by the Render API, not in the public JSON file.

## Test in Stripe test mode

1. Open the live site and create a test account with a strong password (12+ characters).
2. Save one or more companies to the watchlist.
3. Open **My watchlist** and confirm the saved company is shown.
4. Select a plan and complete Stripe Checkout using a Stripe test card, e.g. `4242 4242 4242 4242`, a future expiry and any CVC.
5. In Stripe Workbench/Webhooks, confirm the webhook was delivered successfully.
6. Check that the customer's plan changed in the API response from `/api/auth/me` after signing in again.

## Current MVP boundaries – do not sell beyond these

- Public company search continues to use the public `leads.json` file.
- Watchlists save ACN and company name. Automatic matching against weekly data and email notifications are not yet implemented; those are the next development phase.
- Account email verification, password reset, account deletion/export workflows, stronger abuse/rate controls, operational monitoring and formal privacy/legal review are required before a broad public launch.
- Stripe Checkout is scaffolded but requires your real Stripe Price IDs and webhook secret. Test mode only until end-to-end checks pass.
- Plan limits currently apply to the number of saved watchlist entries (Free 5, Starter 25, Professional 150, Business 500).
- Do not describe a watchlist item as a credit assessment or predict insolvency. Show source dates and encourage checking the original ASIC notice.
- Do not store personal bankruptcy or consumer credit information in this company-monitoring MVP.

## Local development

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

Set `RADAR_SECRET_KEY` to a random secret of at least 32 characters and optionally set `DATABASE_URL=sqlite:///./radar-local.sqlite3`, then run:

```bash
uvicorn backend.main:app --reload
```

API docs: `http://127.0.0.1:8000/docs`.
